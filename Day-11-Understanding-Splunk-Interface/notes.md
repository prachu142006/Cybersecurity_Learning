# Day 11 – Windows Command-Line Auditing & Understanding Splunk Interface

## 1. Introduction

On Day 11, I learned about Windows Process Command-Line Auditing and explored important features of the Splunk interface.

The main objective was to understand how Windows records process execution details and how SOC Analysts use Splunk to investigate and analyze security logs.

## 2. Windows Process Command-Line Auditing

Windows Process Command-Line Auditing helps record the command-line arguments used when a new process is created.

It provides additional information about process execution.

Without command-line auditing, Event ID 4688 may show process creation details without displaying the complete command that was executed.

### Importance

- Identifies executed commands.
- Provides additional process information.
- Helps investigate suspicious activities.
- Improves endpoint visibility.

## 3. Event ID 4688 – Process Creation

Event ID 4688 is generated when a new process is created in Windows.

It helps SOC Analysts investigate process execution activities.

Important information includes:

- New Process Name
- Creator Process Name
- Process Command Line
- Subject Account

### Parent and Child Processes

**Parent Process:** The process that starts another process.

**Child Process:** The newly created process started by the parent process.

Example:

When PowerShell starts cmd.exe:

- Parent Process: powershell.exe
- Child Process: cmd.exe

This relationship helps analysts understand process execution chains.

## 4. Command-Line Auditing Configuration

Windows supports command-line recording for process creation events through the following registry setting:

`ProcessCreationIncludeCmdLine_Enabled`

When enabled, Windows includes command-line information in applicable Event ID 4688 records.

This helps analysts understand not only which process started but also which command was executed.

## 5. Splunk Introduction

Splunk is a SIEM (Security Information and Event Management) platform.

It collects, searches, monitors and analyzes machine-generated data.

SOC Analysts use Splunk to investigate security incidents and identify suspicious activities.

## 6. Splunk Search & Reporting

Search & Reporting is the main application used to search and investigate logs.

It provides features such as:

- Search Bar
- Time Range Picker
- Events
- Patterns
- Statistics
- Visualization
- Fields Sidebar

## 7. Search Bar

The Search Bar is used to execute SPL (Search Processing Language) queries.

Example:

```spl
index=*
```

This searches across all indexes accessible to the user.

## 8. Time Range Picker

The Time Range Picker allows analysts to select the period for searching logs.

Common options:

- Last 15 minutes
- Last 60 minutes
- Last 24 hours
- Last 7 days

It helps analysts investigate activities within a specific time period.

## 9. Events Tab

The Events tab displays individual log records matching the search query.

Important fields:

- `_time` – Event timestamp.
- `host` – System that generated the event.
- `source` – Data source.
- `sourcetype` – Type of data.
- `EventCode` – Windows Event ID.

## 10. Patterns Tab

The Patterns tab helps identify similar events and common patterns in search results.

It helps analysts understand repeated activities in logs.

## 11. Statistics Tab

The Statistics tab displays structured results generated by SPL commands.

Example:

```spl
index=*
| stats count by host
```

This query counts the number of events generated by each host.

## 12. Visualization Tab

Visualization represents search results graphically.

Examples:

- Bar Charts
- Pie Charts
- Line Charts

It helps analysts understand event distribution and trends.

## 13. Fields Sidebar

The Fields Sidebar displays available fields in search results.

It contains:

- Selected Fields
- Interesting Fields

Analysts can use these fields to filter and investigate specific information.

## 14. Splunk Job Inspector

Job Inspector provides detailed information about how a search query was executed internally.

It helps analysts understand:

- Search execution time.
- Events scanned.
- Results returned.
- Execution costs.
- Search processing details.

### Importance

Job Inspector helps identify slow searches, troubleshoot search performance and optimize SPL queries.

## 15. Search History

Search History allows analysts to access previously executed searches.

It helps reuse queries without writing them again.

## 16. Save Search

Save Search allows analysts to store frequently used SPL queries for future investigations.

## 17. Export Results

Export allows analysts to download search results in supported formats such as CSV.

It is useful for reporting and further analysis.

## 18. Importance in SOC Operations

Windows Command-Line Auditing and Splunk interface knowledge help SOC Analysts:

- Investigate process execution.
- Identify suspicious commands.
- Understand parent-child process relationships.
- Correlate Windows Security logs.

- Investigate search performance.
