# Day 11 – Practical: Windows Command-Line Auditing & Splunk Interface

## Aim

To enable Windows Process Command-Line Auditing, investigate Event ID 4688, verify process execution details in Splunk and understand the Splunk interface and Job Inspector.

# Part A: Windows Process Command-Line Auditing

## 1. Enable Command-Line Auditing

Configured Windows to record command-line information in process creation events.

Registry setting:

`ProcessCreationIncludeCmdLine_Enabled`

Configured the value to:

`1`

This enables command-line inclusion in applicable process creation audit events.

## 2. Generate a Test Process

Executed the following command in PowerShell:

```powershell
cmd.exe /c "echo Day11-Test"
```

Output:

```text
Day11-Test
```

This created a test process and executed the specified command.

## 3. Investigate Event ID 4688

Opened:

Windows Event Viewer → Windows Logs → Security

Filtered the Security logs using Event ID:

`4688`

### Observed Results

| Field | Result |
|---|---|
| Event ID | 4688 |
| New Process | cmd.exe |
| Parent Process | powershell.exe |
| Command Line | cmd.exe /c "echo Day11-Test" |

### Observation

Windows successfully recorded the process command-line information after command-line auditing was enabled.

The test process was identified through Event ID 4688.

## 4. Verify Event in Splunk

Executed the following SPL query:

```spl
index=* sourcetype="WinEventLog:Security" EventCode=4688 "Day11-Test"
| table _time host New_Process_Name Creator_Process_Name Process_Command_Line
| sort -_time
```

### Observation

The same Event ID 4688 was verified in both Windows Event Viewer and Splunk.

The command-line information was available in the Splunk search results.

## 5. Learning Outcome

- Configured Windows command-line auditing.
- Investigated Event ID 4688.
- Identified parent and child processes.
- Verified command-line arguments.
- Correlated Windows Security logs with Splunk.

# Part B: Understanding Splunk Interface

## 6. Access Splunk

Opened Splunk using:

```text
http://localhost:8000
```

Logged in and opened the Search & Reporting application.

## 7. Basic Search

Executed:

```spl
index=*
```

### Observation

The query searched across accessible indexes and returned matching events.

## 8. Statistics Analysis

Executed:

```spl
index=*
| stats count by host
```

### Observation

The query counted the number of events generated by each host.

The Statistics tab displayed structured results.

## 9. Visualization

Opened the Visualization tab after executing the statistics query.

### Observation

Search results could be represented graphically using available chart types.

## 10. Fields Investigation

Observed the Fields Sidebar.

Important fields included:

- host
- source
- sourcetype
- _time
- EventCode

### Observation

Fields help analysts filter and investigate specific information from log events.

## 11. Job Inspector Investigation

Opened Job Inspector after executing a search.

### Search Job Details

| Metric | Result |
|---|---|
| Search Status | Completed |
| Search ID (SID) | 1794663083.8 |
| Splunk Version | 10.6.1.1 |
| Server | localhost:8000 |
| User | prachiti |

### Actual Search Results

| Metric | Observed Result |
|---|---:|
| Total Results Returned | 1,160 |
| Events Scanned | 16,899 |
| Search Execution Time | 2.3 seconds |

### Execution Costs

| Component | Duration |
|---|---:|
| command.search | 1.34 sec |
| command.timeliner | 0.92 sec |
| command.search.kv | 0.63 sec |
| dispatch.fetch.rcp.phase_0 | 0.62 sec |
| command.search.typer | 0.33 sec |

### Observation

Splunk scanned 16,899 events and returned 1,160 results in approximately 2.3 seconds.

Job Inspector helped understand how Splunk executed the search internally.

Individual execution cost timings may overlap, so they should not be added together to calculate total search execution time.

## 12. Search Log

Job Inspector also provided access to the search.log file.

The search log contains detailed information about search execution and processing.

It helps analysts troubleshoot search-related issues.

Explored the Search History, Save Search and Export Results features to understand how previously executed searches can be accessed, stored and downloaded.
